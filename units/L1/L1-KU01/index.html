S

Singleton 单例

保证一个类仅有一个实例
创建型

一句话解释

确保全局只有一个实例，并提供一个全局访问点。

类图

反例

// ❌ 多处 new，实例不唯一
const db1 = new Database();
const db2 = new Database();
console.log(db1 === db2); // false

正例

// ✅ 全局唯一实例
class Database {
  static #instance = null;
  static getInstance() {
    if (!this.#instance) {
      this.#instance = new Database();
    }
    return this.#instance;
  }
}
const db1 = Database.getInstance();
const db2 = Database.getInstance();
console.log(db1 === db2); // true

实际架构场景

Spring BeanJDK Runtime数据库连接池

面试考点

懒汉式 vs 饿汉式、双重检查锁定、静态内部类实现、反射攻击防护。

F

Factory 工厂

定义创建对象的接口
创建型

一句话解释

将对象的创建逻辑封装起来，客户端无需关心具体实现类。

类图

反例

// ❌ 直接 new 具体类
class OrderService {
  createNotifier(type) {
    if (type === 'sms') return new SMSNotifier();
    if (type === 'email') return new EmailNotifier();
    // 每加一种通知方式都要改这里
  }
}

正例

// ✅ 工厂封装创建逻辑
class NotifierFactory {
  static create(type) {
    const map = {
      sms: SMSNotifier,
      email: EmailNotifier,
      push: PushNotifier
    };
    return new map[type]();
  }
}
// 新增通知方式只需扩展 map

实际架构场景

Spring BeanFactoryJDK Calendar.getInstance()SLF4J LoggerFactory

面试考点

简单工厂 vs 工厂方法 vs 抽象工厂、与反射结合、Spring IOC 容器的本质。

B

Builder 构建器

分步骤构建复杂对象
创建型

一句话解释

将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。

类图

反例

// ❌ 构造函数参数爆炸
new User(name, age, email, phone,
  address, avatar, role, status, ...);
// 10个参数，顺序容易搞错

正例

// ✅ 链式调用，清晰可读
const user = new UserBuilder()
  .setName('张三')
  .setAge(25)
  .setEmail('zhang@example.com')
  .setRole('admin')
  .build();

面试考点

P

Prototype 原型

通过复制现有对象创建新对象
创建型

一句话解释

用原型实例指定创建对象的种类，并且通过拷贝这些原型创建新的对象。

类图

反例

// ❌ 手动复制所有字段
const user2 = new User();
user2.name = user1.name;
user2.age = user1.age;
user2.address = user1.address; // 浅拷贝！
// 修改 user2.address 会影响 user1

正例

// ✅ 实现 clone 方法
class User {
  clone() {
    const copy = new User();
    copy.name = this.name;
    copy.age = this.age;
    copy.address = { ...this.address }; // 深拷贝
    return copy;
  }
}
const user2 = user1.clone();

实际架构场景

JS Object.create()JDK CloneableRedis 持久化

面试考点

浅拷贝 vs 深拷贝、clone() 与拷贝构造函数的性能对比、原型注册表。

A

Adapter 适配器

转换接口使不兼容类协同工作
结构型

一句话解释

将一个类的接口转换成客户希望的另一个接口，使原本不兼容的类可以一起工作。

类图

反例

// ❌ 直接调用不兼容接口
class OldPayment { pay(amount) { /* ... */ } }
class NewPayment { processPayment(amount) { /* ... */ } }
// 客户端需要判断调用哪个方法

正例

// ✅ 适配器统一接口
class PaymentAdapter {
  constructor(oldPayment) { this.old = oldPayment; }
  processPayment(amount) {
    this.old.pay(amount); // 转换调用
  }
}

实际架构场景

Spring MVC HandlerAdapterJDK Arrays.asList()InputStreamReader

面试考点

类适配器 vs 对象适配器、与装饰器模式的区别、Spring MVC 中的 3 种 HandlerAdapter。

D

Decorator 装饰器

动态地为对象添加职责
结构型

一句话解释

动态地给一个对象添加一些额外的职责，比生成子类更加灵活。

类图

反例

// ❌ 继承爆炸
class Coffee {}
class CoffeeWithMilk {}
class CoffeeWithSugar {}
class CoffeeWithMilkAndSugar {}
// 每加一种配料就要新增子类

正例

// ✅ 装饰器层层包裹
const coffee = new Coffee();
const withMilk = new MilkDecorator(coffee);
const withSugar = new SugarDecorator(withMilk);
// 可以任意组合，无需新增类

实际架构场景

Java IO StreamBufferedReaderSpring AOP

面试考点

与继承的区别、Java IO 中的装饰器链、多层装饰的执行顺序、与代理模式的区别。

F

Facade 外观

为子系统提供统一的高层接口
结构型

一句话解释

为子系统中的一组接口提供一个一致的界面，简化客户端与子系统的交互。

类图

反例

// ❌ 客户端直接调用多个子系统
class OrderService {
  placeOrder() {
    inventory.check();
    payment.charge();
    notification.send();
    logistics.arrange();
    // 客户端需要了解所有子系统细节
  }
}

正例

// ✅ 外观封装复杂流程
class OrderFacade {
  placeOrder() {
    this.inventory.check();
    this.payment.charge();
    this.notification.send();
    this.logistics.arrange();
  }
}
// 客户端只需调用一个方法

实际架构场景

Spring MVC DispatcherServletSLF4JMyBatis SqlSession

面试考点

与中介者模式的区别、外观层是否违反迪米特法则、微服务网关是外观模式。

P

Proxy 代理

为其他对象提供代理以控制访问
结构型

一句话解释

为其他对象提供一种代理以控制对这个对象的访问，可以在调用前后添加额外逻辑。

类图

反例

// ❌ 业务逻辑与访问控制耦合
class Document {
  read() {
    if (this.user.role !== 'admin') { // 权限检查混入业务
      throw new Error('无权限');
    }
    // 实际读取逻辑...
  }
}

正例

// ✅ 代理控制访问
class DocumentProxy {
  constructor(doc, user) { this.doc = doc; this.user = user; }
  read() {
    if (this.user.role !== 'admin') throw new Error('无权限');
    return this.doc.read(); // 转发给真实对象
  }
}

实际架构场景

Spring AOPMyBatis MapperProxyVPN/反向代理

面试考点

静态代理 vs 动态代理、JDK Proxy vs CGLIB、Spring AOP 的实现原理、虚拟代理与保护代理。

O

Observer 观察者

定义对象间的一对多依赖
行为型

一句话解释

当一个对象状态改变时，所有依赖它的对象都会自动收到通知并更新。

类图

反例

// ❌ 硬编码通知逻辑
class OrderService {
  placeOrder() {
    // 业务逻辑...
    EmailService.send(); // 直接调用
    SMSService.send();   // 直接调用
    LogService.log();    // 直接调用
    // 每加一个通知都要改这里
  }
}

正例

// ✅ 观察者模式解耦
class OrderService {
  observers = [];
  addObserver(o) { this.observers.push(o); }
  placeOrder() {
    // 业务逻辑...
    this.observers.forEach(o => o.update(this));
  }
}
// 新增观察者无需修改 OrderService

实际架构场景

Spring EventJDK EventListenerVue Reactivity

面试考点

S

Strategy 策略

定义一系列算法，可相互替换
行为型

一句话解释

定义一系列算法，将它们封装起来，并且使它们可以相互替换，让算法独立于使用它的客户。

类图

反例

// ❌ if-else 判断所有策略
class PaymentService {
  pay(type, amount) {
    if (type === 'alipay') { /* 支付宝逻辑 */ }
    else if (type === 'wechat') { /* 微信逻辑 */ }
    else if (type === 'card') { /* 银行卡逻辑 */ }
    // 每加一种支付方式都要改这里
  }
}

正例

// ✅ 策略模式解耦
class PaymentService {
  constructor(strategy) { this.strategy = strategy; }
  pay(amount) { return this.strategy.pay(amount); }
}
// 运行时切换策略
service.pay(new AlipayStrategy());
service.pay(new WechatStrategy());

C

Command 命令

将请求封装为对象
行为型

一句话解释

将一个请求封装为一个对象，从而使你可用不同的请求对客户进行参数化。

类图

反例

// ❌ 直接调用，无法撤销/重做
class Editor {
  bold() { /* 加粗 */ }
  italic() { /* 斜体 */ }
  // 无法记录操作历史，无法撤销
}

正例

// ✅ 命令封装，支持撤销
class BoldCommand {
  constructor(editor) { this.editor = editor; }
  execute() { this.editor.bold(); }
  undo() { this.editor.unbold(); }
}
// 命令历史栈支持撤销/重做
history.push(command);

T

Template Method 模板方法

定义算法骨架，子类填充细节
行为型

一句话解释

定义一个操作中的算法骨架，将某些步骤延迟到子类中实现。

类图

反例

// ❌ 每个子类都重复完整算法
class PdfExporter {
  export() { /* 验证→查询→转换→写入 */ }
}
class ExcelExporter {
  export() { /* 验证→查询→转换→写入 */ }
  // 大量重复代码，只有"转换"不同
}

正例

// ✅ 模板方法复用算法骨架
class DataExporter {
  export() { // 模板方法
    this.validate();
    this.query();
    this.convert(); // 抽象方法，子类实现
    this.write();
  }
}
class PdfExporter extends DataExporter {
  convert() { /* PDF 转换逻辑 */ }
}
