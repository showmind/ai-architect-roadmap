CAP 定理指出：在分布式系统中，一致性 (Consistency)、可用性 (Availability)、分区容错性 (Partition Tolerance) 三者不可兼得，最多只能同时满足其中两个。

CP 与 AP 系统对比

维度CP 系统AP 系统
核心保证一致性 + 分区容错可用性 + 分区容错
分区时行为拒绝写入，保证数据一致接受写入，可能返回旧数据
典型场景金融交易、库存扣减社交网络、内容推荐
一致性模型强一致性 (Linearizable)最终一致性 (Eventual)
代表系统HBase MongoDB RedisCassandra Dynamo CouchDB
协议示例Paxos / RaftGossip / Quorum

🔒 CP 系统示例

  • HBase — 基于 HDFS 的列式存储，强一致性
  • MongoDB — 主从架构，写操作需多数确认
  • Redis Cluster — 主从复制，分区时牺牲可用性
  • Etcd / ZooKeeper — 基于 Raft 的协调服务

🌐 AP 系统示例

  • Cassandra — 无主架构，最终一致性可调
  • DynamoDB — Amazon 托管，低延迟优先
  • CouchDB — 多主复制，离线优先
  • Voldemort — LinkedIn 键值存储

BASE 理论

BASE 是对 CAP 中 AP 方案的延伸

Basically Available（基本可用） · Soft State（软状态） · Eventual Consistency（最终一致性）

BASE 牺牲强一致性来获得可用性，允许数据在一段时间内处于软状态（中间状态），但最终达到一致。适用于大多数互联网应用场景。
